# 1. Client 端如何被构建与加载

## 1.1 addEntry 的完整参数（旧代码）

`参考/src/node/index.ts:179-182`（拆分后位置）：

```ts
ctx.console.addEntry({
  dev: resolve(__dirname, '../../client/index.ts'),
  prod: resolve(__dirname, '../../dist'),
})
```

- 路径基准：无论从 `src/node/index.ts`（开发）还是 `lib/node/index.js`（构建后）算，`../../` 都正好是仓库根，即 `client/index.ts` 与 `dist/`。
- 另有 browser 端入口 `参考/src/browser/index.ts:23-30`（用 `KOISHI_BASE` 环境变量回退到 `/dist/index.js`，否则 `import.meta.url` 替换成 `/client/index.ts`）——这是 package.json `exports.browser` 对应物，与 console entry 是两回事。（注：重构已砍除 browser 独立入口，此条仅为考据）

## 1.2 运行时如何解析 entry（宿主端，已读源码确认）

- `@koishijs/console/lib/index.js:239-241`：`addEntry` 只是注册 Entry；真正解析在 `@koishijs/plugin-console/lib/node/index.js:114-135`：
  - `getFiles`：对象参数时，`!config.devMode → files.prod`；devMode 且 `existsSync(files.dev)` → `files.dev`，否则 `prod`。
  - `resolveEntry`：devMode 下 URL = `"/vite/@fs/" + 本地绝对路径`（即 client/index.ts 由 vite 中间件实时编译）；非 devMode 下 URL = `uiPath + "/@plugin-" + entryKey`，目录型 entry 自动补 `/index.js`，且**只额外探测 `style.css`**（第 129 行）。
  - `serveAssets`（同文件 136-160 行）把 `/@plugin-<key>/...` 静态映射回本地文件。
- devMode 默认值 = `process.env.NODE_ENV === 'development'`（`plugin-console/lib/node/index.js:286`）。宿主 `koishi.yml:32-33` 的 `console:oyzgdk` 只设了 `open: true`。
- dev 的 vite server 由 `createVite()`（`plugin-console/lib/node/index.js:208-220`）调用 `@koishijs/client/lib` 的 `createServer`，root 是 `@koishijs/client/app`，挂在 `/vite/`。

## 1.3 旧 client 构建脚本（git `432f0cb^:build.mjs`，初始提交时删除）

- node/shared/browser 用 esbuild 打到 lib/，其中 **node 端是 `format: 'cjs'`**——这就是旧代码能用 `__dirname` 的原因。
- client 用官方打包器：`const { build: buildClient } = require('@koishijs/client/lib'); buildClient(process.cwd(), { build: { target: 'esnext' }, esbuild: { target: 'esnext' } })`。
- 末尾把 `dist/index.css` 复制为 `dist/style.css`（因为 prod 目录 entry 只探测 style.css）。

宿主现有 `@koishijs/client@5.30.11` 的 `build()`（`C:/Dev/Bot-Dev/koishi-app/node_modules/@koishijs/client/lib/index.js:44-115`）已经改用 **vite**：入口固定 `<root>/client/index.ts`、输出 `dist/`（`index.mjs` 重命名为 `index.js`）、external 仅 `vue/vue-router/@vueuse/core/@koishijs/client`、内置 `@vitejs/plugin-vue` + `@maikolib/vite-plugin-yaml` + `unocss/vite(preset-mini, preflight:false)`、alias `vue-i18n→@koishijs/client`、`@koishijs/components→@koishijs/client`、scss modern-compiler。它自带依赖：vite ^5.4.10、unocss ^0.65.1、@vitejs/plugin-vue ^5.1.4（`@koishijs/client/package.json`）。

# 4. 校验"能跑"的最短路径

1. 宿主 root `yarn install`（装入新 devDeps）。
2. `yarn workspace koishi-plugin-marketn-refactored build`（产出 lib/ 与 dist/，否则 loader 解析 `lib/node/index.cjs` 直接 MODULE_NOT_FOUND——已实测）。
3. 编辑 `koishi.yml`：注释掉 `market-next:hgaird`，在 group:console 下加 `marketn-refactored:<随机id>: {}`。
4. 宿主 `yarn dev`：console devMode 自动为 true（NODE_ENV=development），`addEntry` 的 `dev` 生效（要求 `client/index.ts` 存在），浏览器访问 `http://127.0.0.1:<port>/`（uiPath 默认空串，`console:oyzgdk` 的 `open: true` 会自动开浏览器）；client 由 `/vite/@fs/...` 实时编译，`virtual:uno.css` 由宿主 unocss 解析——**此路径无需构建 dist/**。
5. prod 校验（可选）：需 `dist/index.js` + `dist/style.css`（注意 prod 只探测 style.css），可用宿主 `yarn build`（yakumo client 步骤）生成，然后 `yarn start` 走 `/@plugin-<key>/index.js`。

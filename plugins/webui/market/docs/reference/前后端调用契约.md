# 策略与算法考据（P6 补全——删除 `参考/` 前的最后抢救）

> 以下为 `参考/src/node` 中未写进上文各节、但删除后无法从产物反推的实现知识。数值均来自参考代码，是"重构前后行为等价"验收与未来调参的唯一依据。

## 附录 A. npm registry 路由与 failover（registry-router.ts / route-health.ts / registry-metadata.ts）

**端点与竞速**：`REGISTRY_FALLBACK_ENDPOINTS` 五镜像按序：`registry.npmmirror.com` → `mirrors.cloud.tencent.com/npm` → `mirrors.huaweicloud.com/repository/npm` → `registry.npmjs.org` → `r.cnpmjs.org`；`REGISTRY_ROUTE_STAGGER = 120ms`（备用端点错峰启动）；`REGISTRY_FAST_ROUTE_THRESHOLD = 800ms`（主端点慢速阈值/竞速触发线）；`REGISTRY_STATS_TTL = 30 天`（路由统计文件过期即丢弃）。endpoint 未配置时用 `get-registry` 包读用户 .npmrc。竞速机制：主端点先发，超 800ms 或失败则全部备用端点按 `120ms × index` 错峰并发，先回先得，其余 abort。

**健康评分公式（`scoreRouteHealth`，两域共用）**：成功率项 `(rate-0.5)*6`；total≥3 且 rate≥0.8 加 1.5、rate<0.35 减 2；历史 score 直加；成功次数 `+min(2, successes*0.25)`、失败 `-min(2, failures*0.2)`；平均延迟分档 ≤300ms +1.5 / ≤fastThreshold +1 / ≤1200ms +0.5 / ≤2500ms −0.3 / ≤4000ms −1 / 更慢 −2；compressionBonus 时 br +0.5、gzip +0.2；10 分钟内成功过 +1.5；连续失败 `-min(5, consecutive*1.5)`。

**记分与冷却**：成功记分 ≤fast 阈值 +0.4 否则 +0.1，failures 衰减 ×0.6，EWMA 均值 `0.7旧+0.3新`；失败罚分按原因：not-found 0.4 / invalid 0.8 / http 1.2 / timeout、network 1.8 / 其他 1.5（market 域固定 1.2）；registry 磁盘落盘 debounce 2s，恢复时 1 天内有成功则 score clamp(-1,3) + failures 截断 `min(failures, max(2, ceil(successes/2)))`，否则 clamp(-4,3) + failures≤12；主端点 demote 条件 `failures≥2 且 selectedScore+1 < primaryScore`；fallbackDelay 自适应：无统计 800ms / 10min 无成功且失败≥3 → 200ms、≥2 → 400ms / avg>4000ms → 400ms / >2500ms → 600ms；端点变更时 routeStats 全部重置。market 域冷却阶梯：1 fail=1min、2=5min、3=30min、4=4h、5+=12h。

**registry 元数据获取（registry-metadata.ts）**：404 缓存 TTL 5 分钟；重试循环 `retry+1` 次，退避 `sleep(300×(retry+1))` 线性；失败原因聚合：全 not-found 才报 not-found，否则取第一个非 not-found（`allRegistryAttemptsNotFound`/`getRegistryAttemptReasons`，错误对象挂 `marketNextReason`/`marketNextReasons` 两个 defineProperty 属性）；版本过滤：`koishi` 包特判 `satisfies(version,'4')`，其他插件 `Scanner.isPlugin && Scanner.isCompatible('4', remote)`；`getVersions` 只保留 peerDependencies/peerDependenciesMeta/deprecated 三键并按 semver 降序；`pickMetadataProbe` 优先 `koishi` → `@koishijs/plugin-console` → 任一插件 → 第一个。

## 附录 B. 市场索引：镜像、版本共识与磁盘缓存（market-internals.ts / market-version.ts / market-router.ts / market-cache.ts / market.ts）

**镜像清单（`FALLBACK_ENDPOINTS`，10 个）**：t4wefan（默认）、gitee 聚合器、`kp.itzdrli.cc`、`koishi.itzdrli.cc`、`registry.koishi.chat`、koishijs.github.io、raw.githubusercontent(release)、cdn.jsdelivr.net、ghproxy.net 代理、ghfast.top 代理。`ROUTE_STAGGER = 80ms`、`FAST_ROUTE_THRESHOLD = 500ms`（注意与 registry 域的 120/800ms 不同）、`FIRST_PAYLOAD_TIMEOUT = 1.5s`、`MARKET_GENERATION_TOLERANCE = 2 分钟`、`MAX_CACHE_ENTRIES = 3`、`CACHE_ENTRY_TTL = 30 天`。usage 镜像文档比 FALLBACK 多一个 `https://koi.nyan.zone/registry/index.json`（Lipraty）与 k.ilharp.cc 论坛链接（见 §1.2）。

**版本见证（共识）机制**：7 个 versioned source 带权威权重：`registry.koishi.chat`(100, authoritative)、`raw.githubusercontent.../release`(95, authoritative)、`koishijs.github.io`(90)、`registry.koishi.t4wefan.pub`(85)、`cdn.jsdelivr.net`(70)、`ghfast.top`(65)、`ghproxy.net`(60)。`version.txt` 放在 `index.json` 同路径（正则替换），内容寻址 URL 为 `index.{64位hash}.json`，hash 须匹配 `/^[a-f0-9]{64}$/`。算法：前 3 个 primary 见证并发；`PRIMARY_DISCOVERY_TIMEOUT = 1.2s` 时若票数一致即定，否则开 secondary；总超时 `VERSION_DISCOVERY_TIMEOUT = 3s`；authoritative 见证返回或票面 authority 总和 ≥160 时立即定稿；选 hash 排序：票数 > 含 authoritative > 最大 authority。preferred 顺序：endpoints[0]、koishi.chat、t4wefan、raw.githubusercontent、github.io。

**获取与降级**：版本化获取失败降级直连；无缓存时投机预取（hardcode t4wefan 为第二候选，等待 300ms（无 resolution）/150ms（有 resolution）后 hash 匹配则采用，不匹配丢弃）；世代（generation）防回退：`minimumGeneration` 取所有缓存端点的 `forceTime||time` 最大值，容忍 2 分钟，低于此值拒绝并转入 rescue（冷却中的端点在活跃端点全失败后作为救援重试，rescue 失败仅罚 0.25 分且不延长冷却）。【重构砍除项：世代防回退与 `primary-stale` 归因未移植，fallbackReason 收缩为 3 值。】

**磁盘缓存 v3 双层结构**：主文件 `cache/market-next-index.json`（store v3：entries + lastUsed + routeStats）+ 分片目录 `cache/market-next-index/`（文件名 = `sha1(endpoint).hex.slice(0,16).json`，只存 result）；原子写 `.{pid}.{ts}.tmp` + rename；挑选评分：age≤12h +3 / ≤3d +1 / 其余 −1 / 是 config.endpoint 再 +0.5，lastUsed 最优先、config.endpoint 次之；条目上限 3、TTL 30 天，写时清理孤儿分片；legacy 内联 store（entries 内嵌 objects 数组）检测后 1s 延迟迁移为分片布局；条件请求头 `if-none-match`/`if-modified-since`（仅非内容寻址请求）；请求头 `accept-encoding: br,gzip,deflate`；响应 hash 为 sha256(解码后文本)。

**getSnapshot 首屏等待策略（market.ts）**：冷启动优先等磁盘预热任务（上限 1.5s）；首次 get 自行触发 warm 且只等 `min(400ms, 1.5s)`；网络仍无果则返回 `loading:true` 的空 payload 并在后台完成后 `refresh('market')`；有缓存而网络失败时返回 `stale:true` + error 的旧 payload；`dataVersion` 仅在 contentHash 变化时递增（payload data 按 dataVersion 记忆化复用）。

## 附录 C. 头像代理细则（avatar.ts）

常量：TTL 7 天、清扫间隔 1h、内存/磁盘各上限 512 条、单图上限 96KB、HEAD 超时 1200ms、GET 超时 3000ms、手动重定向上限 3 次。SSRF 防护：允许主机白名单 7 个（www.npmjs.com / npmjs.com / s.gravatar.com / gravatar.com / www.gravatar.com / cravatar.cn / www.cravatar.cn），白名单外做 DNS `lookup(all)` 解析并逐条检查私网地址；IPv4 私网判定（0/10、127/8、169.254、172.16-31、192.168、≥224 及畸形段）；IPv6（::1、::、::ffff: 前缀、fe80::/10（`first & 0xffc0 === 0xfe80`）、fc/fd/ff 前缀）；blocked：localhost / localhost.localdomain；流式读取超 96KB 中断。默认头像识别：gravatar `d=`/`default=` 参数值 ∈ {default,mp,identicon,monsterid,wavatar,retro,robohash,blank} 视为默认头像不缓存（`d=404` 例外），gravatar 键且 mode≠404 同样跳过；响应头 `avatar-from: default|mp` 判定。缓存键规范化（非法字符→`-`、截 128、空则 sha1 兜底），文件名 `sha1(key).json`；Accept 头 `image/avif,image/webp,image/png,image/jpeg,image/gif,image/svg+xml;q=0.8,*/*;q=0.1`。

## 附录 D. 本地包上传与绑定安全限制（local-upload.ts / local-binding.ts）

分片 512KB、会话 TTL 15 分钟、归档条目上限 8192、解压总大小上限 256MB、package.json 上限 1MB、总大小上限 64MB（`MAX_LOCAL_BINDING_PACK_SIZE`）。tar 参数 `strict:true, maxReadSize/maxMetaEntrySize 1MB, maxDecompressionRatio:200`；条目路径必须以 `package/` 开头、拒绝绝对路径与 `..`、拒绝 SymbolicLink/Link/CharacterDevice/BlockDevice/FIFO、拒绝重复 package.json；base64 分片严格校验（长度 %4、字符集、roundtrip 相等）；uploadId 须匹配 `/^[0-9a-f-]{36}$/i`；canonical 文件名 `{slug-120字符}-{version}.tgz` 尾插 `-{hash12}`（hash 须 `/^[a-f0-9]{12,64}$/i`）；commit 幂等（同 hash 复用、异 hash 报"同名本地插件归档已存在，但文件内容不一致"）；临时目录 `.yarn/local/.market-next-upload`（`.part` 后缀）。本地绑定：`npm pack --ignore-scripts --json --pack-destination`，超时 `max(1min, config.timeout)`；mkdtemp 前缀 `.market-next-pack-`；`file:.yarn/local/{filename}` 请求串；并发绑定竞态靠"rename 失败后重验目标 hash"解决。约 20 条用户可见中文错误文案（"请使用 npm pack 生成的 .tgz"、"归档中的包名不是有效的 Koishi 插件名称"等）。

## 附录 E. 安装编排细节（installer.ts / installer-transaction.ts / install-history.ts / bundle-installer.ts）

**安装前本地插件保护**：包管理器执行前，对"已安装、registry 形态、来源未确认"的依赖逐一 getPackage 确认；全部路由 404 → `markRegistryNotFoundDependency`（改判 unbound local，去掉 latest、清 invalid）；结果不确定时抛中文错误"暂时无法确认以下已安装插件是否来自 npm：{names}。为避免包管理器误下载本地插件，本次操作已取消；请检查 npm 网络后重试。"；存在 unbound 本地依赖时抛"检测到来源未绑定的本地插件，继续安装会让包管理器尝试从 npm 下载它们：{names}。请先在"本地插件"分组中绑定来源或移除这些依赖。"。

**包管理器调度判定**：`requiresPackageManager`——forced 恒真；删除恒真；local↔非 local 切换真；已 resolved 且 `satisfies(resolved, request, {includePrerelease:true})` 则可跳过包管理器（只写 package.json）；`hasDependencyRuntimeChange`（fullReload 判定）——resolved 变化 / 本地依赖请求变化。

**已知 quirk**：`require.resolve(name) in require.cache` 可能抛错（上游 FIXME koishijs/webui#273）；fullReload 延时 `FULL_RELOAD_DELAY = 1s`；override 写 package.json 时依赖按 `localeCompare` 排序、2 空格缩进+尾换行。

**安装日志**：文件名 `{ISO时间戳(:.→-)}-{deps概要截80字符}.log`，元数据 `.log.json`（version 1，changes 的 afterResolved 成功后回填）；详情上限 512KB（head 128KB + tail 384KB，中间插 `... N bytes omitted ...`），无元数据时预览 8KB+32KB；ANSI 清洗两条正则（OSC `\u001B]...\u0007/\u001B\\` 与 CSI 序列）+ 孤立 `\r`；legacy 按日志内容正则推断 status；retention：`installLogRetentionHours`（≥1h）> 废弃的 `installLogRetention` > 默认 3 天；getHistory clamp(1,50)。

**marketData 迁移与 bundle 安装**：`migrateFromConfig` 仅当 store 为空才从插件配置迁 updateIgnored/bundleRecords/collapsedGroups；`collapsedGroupsVersion=1` 迁移会删除 legacy `installed` 键；dispose 时 flush；原子写。bundle 安装：直接环检测（bundle↔member 互引）；成员配置键 `~{shortname}:{bundleMemberIdent}`（一律禁用态写入，preset 时值为 member.config）；move 语义（组外已有配置移入组、键冲突回退 ident 键）；`record.installedByBundle` = 安装前不在 dependencies。

## 附录 F. 环境快照（environment.ts）

上限 60 条、按 lastSeenAt 降序；ID = `env-{sha256(canonical).slice(0,20)}`，canonical 只含 `[name, local?request:(resolved||request), source, local]`——**request 的 `^`/`~` 差异不改变 ID**（同环境重装不产生新快照）；Windows rename 遇 EEXIST/EPERM 先删再 rename；diff 状态机顺序 unchanged→unsupported(local)→added→removed→upgrade/downgrade（双 valid semver 才 compare）→changed；恢复时 unsupported 本地依赖直接拒绝（中文文案"目标环境包含无法自动恢复的本地依赖"）。

## 附录 G. 环境变量与杂项 quirk

- `GRAVATAR_MIRROR` 环境变量（market.ts）：gravatar 基址切换开关，client 据此切换 gravatar 基址。
- legacy scanner 模式（无市场索引、走 npm registry analyze）两个 npmmirror quirk：npmmirror 404 静默忽略；npmmirror 缺 `links` 字段时补 `links.npm = endpoint.replace('registry.','www.') + '/package/' + name`。另有 `object.ignored` 字段过滤（现代索引模式剔除被忽略条目）。
- logLevel 过滤按 `['silent','error','warn','info','debug']` 序数比较；debug 级镜像为 `[debug]` 前缀的 **info** 记录（Koishi 日志页隐藏 debug 的绕过）。
- 包管理器 exec（package-manager.ts）：`which-pm-runs` 检测；yarn≥2（coerce+gte）追加 `--json` 并逐行解析 YarnLog（仅 `{` 开头行尝试）；npm/pnpm 自动在参数前插入 `install`；信号终止或无退出码 → **−1**；yarn 级别映射 warning→debug、error→warn。
- 私有 API quirk：`ctx.scope[Symbol.for('koishi.loader.record')]` 递归找父上下文；`ctx.loader.writeConfig(true)` 的 true 参数；直接调用 `ctx.console.listeners['config/request-runtime'].callback.call(null, name)` 请求运行时创建配置。
